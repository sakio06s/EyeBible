# TagBible 小組共用設定

目前使用同一個 Supabase 專案。小組資料與個人私人備份分開，無須購買服務或設定額外 API 金鑰。

## 資料庫啟用
1. 先確認已經執行過 `cloud/schema.sql`（個人同步）。
2. 到 Supabase → SQL Editor → New query。
3. 貼上本分支完整的 `cloud/groups.sql` 並執行一次。這是新增小組資料表與 RPC 的 migration，可以重跑，不會刪除個人資料，也不會把私人筆記改為公開。
4. 預覽版的 `cloud/config.js` 使用 `groupsEnabled: true`。尚未套用 migration 時，小組頁會顯示尚未啟用；個人同步仍獨立運作。可將此旗標設為 false 暫停小組介面，不影響私人儲存。

全部小組表開啟 RLS，匿名沒有存取權。已登入者也不能直接查寫資料表，只能使用 `group_action` 和 `group_read`，每次在伺服器確認身分、成員資格與作者／組長權限。沒有新的公開資料表自動授權。經文快照會在伺服器驗證並保留標準欄位，無效內容或超出範圍的經節會拒絕。未要求 Realtime publication；沒有定時輪詢。小組頁到頂後再下拉、返回瀏覽器或恢復連線時更新；本機操作送出成功後立即重新讀取。

## 第一版規則
- 每帳號同時一個小組。組長建立，成員確認小組名稱後使用邀請碼加入。
- 邀請碼 **30 天有效**；組長產生新碼後，舊碼立即失效。只有組長可在設定內查看目前可用碼。
- 邀請碼等同邀請資格，請分享給預定加入的成員。已被移除的人即使持有碼，也需組長先解除限制。
- 一般成員可退出。組長暫不能退出或移交；第一版不提供刪組。
- 只有加入後新存為分享的筆記、新回覆、阿們與新簽到會傳到這個小組。加入前的資料不自動公開；私人筆記、標註和閱讀設定只存個人備份。
- 小組成員看到公開名稱、頭像、簽到日期；不會看到 Email 或 Google 憑證。
- 互動頁先顯示 5 筆，沒有七天限制。點「載入更多留言」每次再顯示 5 筆（10、15、20…）；單純捲動不會載入。伺服器仍每頁取 10 筆並在前端暫存，未顯示的資料不會跳過。互動頁只用一層整頁捲動，不再在留言區內外切換手勢；簽到頭像接在已展開的留言之後。所有有回覆的留言優先，再依最近回覆時間排序；沒有回覆的留言依發佈時間由新到舊。足跡選日期後，可分頁看當日完整小組討論。貼文依發佈日期歸檔，引用的經文日期另存，閱讀舊經文後的新分享不會被錯歸到過去。
- 不依天數刪除或隱藏留言。背景更新保留已載入的分頁及回覆範圍。作者可刪除自己的公開貼文與回覆，組長可以管理不當留言；刪除留下 tombstone 防止重試復活。個人筆記原件仍保留。
- 今日完成者外框發光 1–5 級，相鄰完成日加一，漏掉完整日降一。小組等級從實際分享給這個小組的簽到日期計算。
- 未讀數計同組所有保留貼文中的他人貼文與回覆，不包含阿們或自己的內容。打開頁面僅標記畫面實際顯示的活動，完整歷史回覆仍在足跡。

## 斷線與待送內容
個人同步與小組傳送有不同的狀態。個人儲存成功不等於小組分享成功。小組待送項目保存在目前帳號的瀏覽器 outbox，保留原小組、操作 ID，每項分開儲存，兩個分頁不會互相覆寫；伺服器保留操作收據，重送不重複新增，也不會把已接受過的舊阿們／簽到選擇重新套用到另一裝置的較新選擇。退出／換組後，舊項目不會改送新組。若瀏覽器拒絕儲存，畫面會提示，請先保留個人紀錄。未加入小組時的新筆記先存個人紀錄。

組長移除成員會阻止後續存取。對方再次連線檢查成員資格後會清除小組畫面。任何人先前已看到的內容無法遠端收回；離線裝置不能即時接收移除通知。離組時清除小組分享草稿；已勾選私人的同帳號草稿保留在個人編輯器。換帳號會清除所有舊帳號草稿。

公開照片只在目前成員名單傳輸一次，留言使用短暫的本機圖片網址重用，避免每則回覆重複攜帶照片。離組成員的歷史留言保留名稱與預設圖示，不另存公開照片副本。

## 真實驗收（目前仍待完成）
1. 帳號 A 登入預覽版，在「我的設定」確認標註、私人筆記、簽到已同步；另一瀏覽器登入同帳號，確認三者都存在。
2. A 到小組頁建立小組，複製邀請碼。帳號 B 在另一瀏覽器登入、貼碼、確認名稱後加入。
3. A 新增公開分享。B 能讀取、回覆、按阿們；A 返回頁面能看到更新。
4. A 新增私人筆記，B 在互動與足跡都不能看到。
5. A、B 完成今天讀經，兩邊都顯示正確簽到名稱和發光狀態。
6. 足跡選擇有留言的日期，確認回覆與經文引用可查閱。自動測試已用舊日期 fixture 驗證互動牆可載入舊留言，足跡依日期保留全部歷史。
7. A 換邀請碼，舊碼不能用；移除 B 後，B 返回小組頁失去存取權，舊碼不能重入。A 解除限制後，B 可用有效新碼加入。
8. 斷線新增分享，確認待送狀態；恢復連線後只出現一次。登出／換帳號後不顯示上一個帳號的小組內容。

未取得已登入的 Supabase 後台或資料庫連線時，助理只能準備、測試並發佈 migration，不能宣稱已替使用者執行到正式專案。一般 publishable key 沒有建立資料表的權限；請勿將資料庫密碼、service-role key 或 OAuth secret 貼到聊天中。

## 2026-11-19 留言板更新

已安裝過小組的專案，也需要重跑最新版 `cloud/groups.sql` 一次。這次新增回覆阿們、回覆活動排序欄位和 `group_feed` RPC，並更新既有回覆的排序資訊；不刪除原本小組、成員、邀請碼、留言、私人筆記或簽到。新版互動牆使用 `group_feed` 每頁取 10 筆，介面每次顯示 5 筆。v0.14.0 的介面更新不需要重跑 SQL。`group_read` 的日期足跡保留每頁 20 筆，原 recent 模式僅為舊客戶端相容，不是新版互動牆資料來源。

若更新 SQL 已成功但 API 仍暫時回報找不到新功能，最新版腳本結尾包含 `notify pgrst, 'reload schema';`，通知 Supabase 重新載入 API schema。查詢小組狀態尚未完成或失敗時，畫面不再當成「尚未加入」，而是顯示載入／重試；只有伺服器成功回覆沒有小組，才顯示建立或加入表單。這些查詢不改變原成員資格。

### v0.14.0 介面與更新

小組名稱、建立／加入小組及「小組設定」集中在「我的設定」帳號區塊下方；留言板移除重新整理鈕。阿們使用 SVG 愛心與固定寬度數字，反應更新只改按鈕狀態，保留留言與焦點。新回覆會重新排序，位於頂端時直接顯示；深入閱讀時保留原本閱讀位置，自己送出回覆則回到置頂留言。正在輸入回覆時保留草稿與游標，結構更新延後至輸入結束。

### v0.14.1 捲動與大小

移除互動頁視覺標題；上方發文入口為「我要分享...」。阿們文字13px、愛心14px，和回覆／查看經節垂直置中，觸控高度維持42px。版本號以9px放在頁首頭像左側，不浮在頭像上。所有筆記／分享儲存按鈕統一「儲存/分享」，讀經頁導向按鈕為「小組互動」。

背景輪詢仍為5秒，可見頁面一小時約720次檢查；已展開多頁／足跡時還會有額外讀取。代價是流量、電量、伺服器負載及Supabase用量，更新也要等輪詢加網路時間；分頁不可見時暫停定期檢查。這次未改成Realtime，沒有新增資料庫設定。

### v0.14.2 下拉更新

取消每5秒定期讀取。小組頁先滑到最頂，再往下拉約72px，看到「放開即可重新整理」後放開手指才更新。不影響原本單層滑動；短拉、橫滑、多指、手勢取消或收回都不更新。更新提示不占內容高度，保留已展開的留言數量，自己送出後立即同步。初次載入、回到瀏覽器與恢復網路仍會更新。阿們計數改為一般文字空格，數字靠近文字，預留空間放在尾端以保持按鈕穩定。無新SQL。

### v0.15.0 分享與回報

小組發文入口固定在Logo下方，開啟獨立純文字分享視窗，不再帶入經文或私人筆記選項。一般分享仍保留於個人紀錄與小組歷史，重載後不會補上舊經文。讀經區的經節／私人筆記另用原工具。設定頁小組卡標題為「我的小組」，最後新增「問題回報」。寄信需另外完成[伺服器設定](feedback-setup.md)，設定前保留原稿並顯示尚未啟用。此介面更新不需新的SQL。

### v0.15.1 最新互動與站內回報

發表新分享與回覆都依最後互動時間排序，直接分享可排在較舊的討論之前。按鈕只顯示「分享」，個人歷史仍自動保存；動作按鈕改為12px等距的緊密排列，小組名稱使用一般內文、不加粗。

Email方式已取消。請依[站內回報設定](feedback-setup.md)執行一次`cloud/upgrade-support.sql`，同時啟用新排序、回報資料表及管理者權限。管理者登入地址只放在私有設定檔／SQL編輯器，不公開在頁面或前端程式。

## 建立小組權限

建立小組只開放既有全平台管理者（與問題回報管理者相同），一般組員透過邀請碼加入。先完成管理者設定，再執行 [管理者建立小組升級](../cloud/upgrade-admin-group-creation.sql)。SQL 會在資料表 INSERT 端限制舊版／自行呼叫 API 的建立行為，另提供只含布林值的能力查詢。前端查詢失敗預設顯示尚未開啟。只部署前端不代表資料庫限制已套用。

本次發布前清除的操作與直接設定連結見 [發布前維護](launch-maintenance.md)。合併維護 SQL 同時包含上述權限升級，不必重複執行。

## 修改筆記與小組留言

已啟用小組的專案，另執行 [upgrade-text-editing.sql](../cloud/upgrade-text-editing.sql)。這是可重複執行的新增 RPC，不清除現有資料，也不修改既有管理者設定。

管理者 SQL 編輯器：https://supabase.com/dashboard/project/mddbzoagloktnwoszuvj/sql/new

- 作者可修改自己的筆記、留言、回覆；組長不能修改別人的文字。
- 原日期、經文、公開／私人屬性、回覆及阿們保留。
- 已連結的公開筆記與原留言同步修改。未建立連結的舊資料不按文字相同自動認定關係，修改前須選擇要同步的原留言／個人筆記。
- 其他分頁已更新同篇內容時，拒絕覆蓋舊版本，保留編輯框文字讓使用者重新確認。
- 找不到原小組留言或已離開原小組時，個人紀錄仍可修改，不能繞過小組權限修改原留言。
- 未套用 SQL 時，小組修改會顯示尚需資料庫設定；原本的讀經與留言功能仍可使用。
