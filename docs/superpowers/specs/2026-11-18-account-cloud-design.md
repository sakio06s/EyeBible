# 登入與個人雲端儲存
使用者已授權開始登入＋雲端儲存。採 Supabase Auth + PostgreSQL，保留現有 Vercel 靜態部署及本機離線操作。依使用者 2026-11-19 的選擇，先完成 Google 登入；Email 驗證碼保留作相容性測試，不在目前入口啟用。實際啟用需使用者的 Supabase 專案及公開連線設定，無設定時保持目前本機功能。

此階段同步個人姓名、頭像、設定、經文快照、標註、筆記、簽到、回覆與已讀狀態。小組共享屬於另一權限邊界，尚不公開個人資料，也不把私人筆記改為共享。

## 實作選擇
保留單頁加獨立 cloud 模組，比整站改框架及自建驗證伺服器更符合既有部署。使用固定版本的 Supabase 官方 SDK（本地供應），避免自行處理驗證碼、權杖刷新或第三方 CDN 載入依賴。

## 資料與權限
個人資料每帳號一列，以 RLS 限制只有本人可讀，寫入 RPC 使用 auth.uid()、預期版本及固定 search_path，防止其他帳號存取與無聲覆蓋。前端將狀態轉為具穩定鍵的紀錄，以三方合併保留不同裝置的獨立變更；同一紀錄衝突需明確選擇，不自動覆寫。

第一次登入保留原本本機資料，先選擇是否匯入；匯入不會把資料放進另一帳號。帳號快取分開保存，登出復原訪客資料並移除顯示中的帳號資料。連線失敗顯示待同步，資料仍保存在本機；工具或書寫框開啟時延後套用雲端更新。

## 驗證
Node 實測穩定鍵編解碼與三方合併（新增、刪除、衝突）；本地 PostgreSQL 驗證 RLS、跨帳號禁止、版本衝突與匿名禁止。Playwright 驗證未設定不影響本機使用、登入/匯入/同步/離線/登出隔離流程，及原有回歸。
