# 固定小組發文與問題回報 — v0.15.0

## 小組分享與讀經筆記分開

「我要分享...」以sticky固定在Logo下方。小組專用底部視窗有自己的頭像、標題及文字區，提示「寫下你想跟大家說的話」，不含經文標記、引用或私人選項。讀經筆記保留經節與私人選項，提示改成「寫下你對這段經文的感動、想法或疑問」。三個互動按鈕使用等寬區段與相同間距。設定頁小組卡先顯示「我的小組」，下面是小組名稱與管理功能。

一般分享以kind=group儲存在個人紀錄，日期用實際送出時的台北日期，獨立於目前開啟的讀經日。RPC省略reading欄位（不是JSONnull），因此既有SQL會儲存無經文的純文字貼文。初始化與足跡不把這類分享補上舊示範經文。既有筆記與經節分享保持原樣。置頂發文列占用的高度納入留言定位與未讀可見範圍，自己的回覆不會被發文列遮住。

## 問題回報

設定頁最後一張卡開啟獨立回報表單。必須登入才能送出；內容／操作ID在失敗時保留，修改內容才開始新操作。重試的姓名與內容也凍結，避免改個人資料後破壞寄信服務去重。換帳號或登出會關閉並清除舊稿，舊請求回應不能影響新帳號。

帳號模組僅把使用者主動填寫的回報、顯示名稱及操作ID傳到同源API，使用目前帳號的Bearer token。API向Supabase驗證，再使用伺服器環境設定的固定收件者寄出純文字信件；不接受前端指定收件人、不傳私人筆記／完整個人狀態、不公開管理者地址與寄信金鑰。服務未設定或送出狀態不明時，介面顯示提示且保留原稿。

實際收件Email／既有寄信服務尚未由使用者提供。本次只準備Resend傳輸與設定說明，沒有建立外部服務帳號、設定真實金鑰或送出真實郵件。上線寄信必須完成[伺服器設定與收件驗收](../feedback-setup.md)。API單個執行個體限流不是serverless跨執行個體的持久全域限額；去重遵守寄信服務有效期間。

## 驗證與審查

Chromium／WebKit驗證獨立分享介面、無經文請求、重載後不附上舊經文、私人讀經筆記不公開、sticky位置／等距按鈕、組別變更時關閉草稿、回報失敗重試與操作ID／姓名不變。實際帳號模組測試檢查每個使用者的Bearer、登出後清稿與忽略舊回應。API測試以假的Auth與Resend回應驗證401／403、方法／長度／UUID型別、固定收件人、純文字、去重、限制、缺少設定與上游失敗。

一輪獨立審查沒有Critical／Important問題，提出姓名換行可能讓郵件中繼資料看起來像另一個欄位。加入失敗測試後，把CR／LF／Unicode換行轉成空格，保持姓名單行。沒有延期的審查項目。既有群組測試已涵蓋省略reading的SQL操作，本次沒有修改或重跑資料庫migration。

Ruling: 寄信設定是唯一尚未具體啟用的外部依賴。預覽介面與API可先檢查，不能把模擬服務測試稱作真實寄達；實體Safari鍵盤／朗讀仍需手機確認。
