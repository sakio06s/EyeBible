# 下拉更新與阿們計數 — v0.14.2

取消小組每5秒輪詢。保留初次載入、回到瀏覽器、恢復網路與自己成功送出後的更新；他人的新留言可在小組頁頂端下拉取得。仍使用單層main捲動、每次按鈕展開5筆，重新取得資料不把已展開數量退回5筆。

手勢須從最頂端開始，單指往下拉至少72px，放開時才執行。只有確認垂直下拉後才攔截瀏覽器回彈，正常上下捲動、橫滑、多指及文字編輯保持原本行為。短拉、手勢取消、拉下後收回、放開時已離開頂端都不重新讀取。提示使用固定定位，不推動內容；同時只允許一個下拉更新。失敗保留現有留言並提示重試。帳號／小組／分頁切換使舊手勢失效。

阿們文字與數字改用一般inline空格，距離與「回覆 1」一致；避免把預留數字寬度置中造成空隙。預留寬度移到整段標籤尾端，保留99→100時按鈕與旁邊動作位置穩定、透明背景、SVG與鍵盤焦點。零反應不顯示數字。

## 驗證與審查

新增pull-refresh測試：捕捉5000ms計時器，確認沒有輪詢；比較阿們／回覆的實際數字間距；驗證短拉、方向、取消、收回、觸點、非頂端、文字編輯、其他分頁、更新中重複、失敗／重試、草稿與已展開數量保留、提示不占高度。Chromium再用原生CDP觸控補驗；WebKit採合成Touch Events驗證狀態機。原有留言、資料隔離、邀請、成員恢復、同步競態等48項邊界案例及私人跨瀏覽器同步保留。

一次獨立審查發現：僅記錄最後touchmove距離，會漏掉瀏覽器合併的最後移動。先重現「移到80px卻只在55px處放開仍更新」的失敗，再依touchend.changedTouches的實際觸點、距離、方向與放開時scrollTop判斷。反向案例（最後move68px、放開80px）、錯誤觸點、橫向放開及離開頂端也加入測試並通過。另修正測試輸出的措辭，明確區分Chromium原生與WebKit合成觸控，沒有延期的輕微項目。

Ruling: 工作區沒有實體iPhone及VoiceOver裝置，不能宣稱已驗證真機回彈與朗讀。以瀏覽器手勢、狀態機、role=status／aria-live／aria-busy與延遲／失敗RPC測試驗證；實際Safari手感仍由使用者手機確認。沒有修改SQL、雲端權限或付費設定。
