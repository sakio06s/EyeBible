# 日期選單與補簽窗口 — v0.15.2

今日讀經的日期區覆蓋原生select，旁有13px低對比下箭頭，日期本身可點。選項文字恰為「今天、昨天、前天」，依Asia/Taipei計算跨月／年日期。選後顯示相對日名與完整日期，載入對應的每日經文。原生select沿用手機、鍵盤與輔助科技操作，不新增對話框依賴。

指定日期只接受驗證相符的正式每日快照，從date或date~daily取快取；shared快照不冒充每日內容。無快取時用既有固定來源代理／daily JSON讀取，指定日期失敗不以latest冒充。背景今日流程保留預設啟動／跨午夜行為，但不能覆蓋手動補讀；快速操作只採最後一次，換帳號、足跡／筆記／分享跳轉取消舊請求。選取明確日期後，重新取得按鈕重試該日期；午夜若原本跟隨今天，取消舊請求並恢復新今日更新。

所有入口共用同一簽到按鈕與處理函式，只允許今天、昨天、前天；更早的經文仍可讀、標註、寫筆記。舊的已完成紀錄保留，按鈕停用並顯示「已完成讀經」；未完成顯示「已超過補簽期限」。不論從足跡、筆記查看經節或小組分享進入都適用。這是本版本App互動限制，既有資料庫的日期儲存／同步格式與歷史紀錄不變，不需SQL migration。

載入中若使用者開啟筆記、選節、切頁或向下閱讀，回應先保存為pending，沿用「載入新經文」按鈕確認。寫作期間不改activeReading，避免把原日期筆記配上另一段經文快照。

## 測試與審查

新增recent-reading.cjs在缺少選單時先失敗，再驗證兩個瀏覽器的三選項、正式經文／離線快取、相對日期、日期別標註／筆記／簽到、實際小組模組送出的complete日期、焦點與背景更新、快速切換、錯日期／404與重試、帳號隔離、跨年，以及舊分享與足跡不能補簽、已完成保留。後加補簽期限時先觀察舊分享仍可簽到的失敗，再修正處理函式與disabled狀態。

一輪獨立審查找出6項Important與1項Minor，全部有Chromium／WebKit的失敗重現：共享快取取代每日內容、筆記跳轉未取消請求、明確今天選擇仍套用舊日fallback、跨午夜忙碌旗標未清、寫筆記期間切換造成公開快照錯配、選項額外附日期，以及換帳號殘留載入提示。最後一項重新評估為會誤導新帳號狀態，一併修正。另驗證在手動選擇前已送出的背景fallback也不能覆蓋新意圖；先失敗再補回應端檢查。recent-reading-edges.cjs完整保留這8個案例，沒有延期項目。沒有第二輪重複審查。

預覽與手機界線：本次只更新預覽分支，不合併main，不修改真實Supabase。Chromium／WebKit自動化使用固定日期與API fixtures，不代表實體iPhone原生日期選單或真實Google帳號的手機驗收。
