# 小組共用驗證 — 2026-11-19

已依使用者確認完成第一版程式：每人同時一組、組長建立、邀請碼 **30 天**有效；同組公開分享／回覆／阿們／簽到／未讀、七天互動牆、完整日期足跡、組長移除與解除限制。私人筆記與標註仍在獨立的本人資料表。

## 證據與限制
- PostgreSQL 17 臨時容器：匿名／直接表格存取／非成員／有效本組資格搭配他組文章 ID 都被拒絕；測過邀請期限／換碼、封鎖重入、作者與組長權限、重複傳送與刪除 tombstone、舊留言歸檔與 keyset 分頁、同帳號同時加入兩組只能成功一組。
- 收據測試：已接受但回應遺失的阿們／簽到操作，重試不能撤銷另一裝置較新的相反選擇。無效經文快照與超出範圍的節數被拒絕。200 則回覆的 fixture 確認初始只傳 100 則及其已讀標記，照片不在每則回覆重傳。
- Chromium、WebKit：建立／邀請確認／加入、分享與私人筆記隔離、回覆／阿們／完成、斷線回應遺失後重新載入、舊組待送項目隔離、歷史多頁、換帳號與移除後清除。
- 12 個獨立邊界情境各跑兩種引擎：台灣回覆日期、照片 Blob 重用、未入組個人簽到、相同經文的語意識別與不同版本隔離、私人草稿保留／分享草稿清除、多分頁待送內容、舊組延遲分頁、已展開動態牆更新、足跡頁數與回覆展開保留。
- 保留既有介面、社群、經文更新／日期切換、標註、Google 登入、手機鍵盤、個人同步與帳號隔離測試。個人跨 Chromium/WebKit 的測試使用真實 SDK 及模擬 API；SQL 權限使用真實 PostgreSQL。
- 已進行一次獨立程式審查；重要發現補上失敗重現後修正，沒有待處理的重要項目。回覆午夜日期雖原列輕微，依台灣日期慣例提升為需要修正，已驗證。

**仍不是正式雲端驗收：** 使用者已確認另一瀏覽器可登入，尚未明確確認三項個人紀錄的真實跨裝置結果。公開 API readiness 回傳 `404/PGRST202`，代表目前專案尚未安裝小組 RPC。沒有可以建立表格的已授權 Supabase 管理工具，因此僅準備並發佈 migration，沒有宣稱已執行到使用者資料庫。後續依 [啟用及雙帳號驗收](../groups-setup.md) 執行。

## 實作決策與取捨（完整紀錄）
1. 沿用既有功能分支直接實作，保留主站部署；一次獨立完整審查。若正式測試失敗，修正在預覽分支，不影響正式版。
2. `group_read` 增加選填 `p_post_id` 以分頁載入回覆，避免截斷歷史；客戶端多管理一個回覆游標。
3. `groupsEnabled` 明確開關，預覽啟用；未設此旗標的舊整合保留原本行為。migration 缺少時只顯示小組服務未啟用，不把個人同步也標成失敗。
4. 私人與小組是兩條獨立儲存路徑，第一次加入不發布舊資料；可能需要使用者重新分享想公開的歷史內容，換來明確的公開同意。
5. 每項待送操作使用獨立 localStorage 紀錄與固定目的組別、操作 ID；伺服器保存 set-operation 收據。這會增加少量儲存，保護多分頁內容與跨裝置選擇。
6. 同帳號失去／改變小組時，清除小組分享草稿，已勾選私人的草稿保留並取消原小組目的地；換帳號清除所有舊帳號草稿。取捨是分享草稿不在失去權限後保留，私人草稿不因背景載入而遺失。
7. 相同經文依日期、參照與每節內容比較，不依 JSON 欄位順序。不同版本放在獨立快照；歷史可能有多個相同日期的版本，避免覆寫自己的經文與標註。
8. 更新時重讀已載入的貼文頁數與回覆範圍，而非凍結或重設第一頁；會比只讀第一頁多一些查詢，保留歷史位置並反映新留言及管理刪除。
9. 照片每名目前成員傳一次，畫面重用 Blob URL；離組作者的歷史保留名稱與預設圖示，不另存照片副本。避免長討論重複放大照片傳輸／DOM，取捨是不保留離組者的照片外觀。
10. 沒有後台管理連線，就由使用者在自己的 SQL Editor 執行已測試、可重跑的新增 migration；公開 publishable key 不升權、不請使用者傳密碼。真實雙帳號結果之前，PR 保持草稿且不更新正式主站。
