# 站內問題回報與管理者設定

本版本已取消Email寄送，不需要Resend、SMTP、寄信金鑰或Vercel收件環境變數。使用已登入的Supabase帳號，透過受權限檢查的feedback_read／feedback_action RPC儲存與管理回報。

## 現有專案啟用一次

1. 管理者須先用指定的Google帳號登入EyeBible一次，且Google身份的Email已驗證。
2. 在Supabase SQL Editor執行準備好的私有升級檔；或複製`cloud/upgrade-support.sql`，把最後的`__ADMIN_LOGIN_EMAIL__`改成管理者登入信箱後執行。
3. 重新整理測試版v0.15.1。管理者「我的設定 → 問題回報」會顯示問題列表；其他使用者保留填寫表單。

升級新增回報、管理者與閱讀狀態資料表，並更新小組最新互動排序函式。原有留言、成員、私人筆記與簽到保留。腳本可重跑；若管理者帳號不存在、未驗證或沒有相符的Google身份，整個交易回滾並要求先登入。管理者身份以私有資料表中的使用者ID判定，登入信箱只用於SQL設定，不送到瀏覽器。公開SQL使用占位符，填妥的私有設定檔不要加入公開儲存庫。

## 功能規則

- 一般使用者只能送出自己的問題或建議；組長不會自動成為全平台管理者。
- 管理者可查看提供者、日期、內容，按「已處理」或「刪除」。刪除會從列表移除並留下伺服器墓碑，避免網路重試把它重新送出。
- 問題列表每次20則，「載入更多回報」取得更舊的資料。開啟的一頁標記為已讀，尚未開啟的頁面仍可保留提醒。
- 首頁提示、頭像與「我的設定」圖示顯示新回報數。首次載入、回到瀏覽器、進入首頁／設定或小組下拉更新時重新取得；沒有定時輪詢。
- 身份與管理權限由資料庫確認，回報資料表與內部函式不直接授權給一般登入者。每帳號10分鐘5則以資料庫交易鎖與持久資料限流；同一操作ID的網路重試不重複建立，也不重複計次。
- 登出／換帳號立即清除舊管理列表與草稿，過期回應不能把資料帶回新帳號。
